Case study · public source

Search the shelf. Keep the cart.

Bookify is a JavaScript MERN bookstore prototype. It reads a MongoDB-backed catalog, filters titles in the browser, registers and logs in readers through Express endpoints, and keeps the cart across refreshes with local storage.

01 / The brief

A small commerce loop with honest edges.

The source covers the path from catalog discovery to cart review. It also makes the current boundary clear: checkout is a visible interface state, not a connected order or payment workflow.

Interface

React routes with shared search

The app keeps one search query in its top-level component and passes it to both the home shelf and the full catalog.

Server

Express endpoints for books and readers

One route returns the MongoDB book collection. Signup and login routes create readers, reject duplicate emails, and compare hashed passwords.

Browser state

Account and cart state survive refreshes

React contexts restore the signed-in reader and cart from local storage. Cart additions are de-duplicated by book ID.

02 / Core flow

Follow one title from catalog to cart.

Each step maps to a public route, component, context, controller, or model in the pinned source revision.

  1. 01

    Fetch the catalog

    The React catalog requests the book collection from Express. The controller returns every MongoDB book record with its name, title, price, category, and image fields.

    GET /book
  2. 02

    Narrow the shelf in the browser

    Search matches book names or titles without case sensitivity. The home shelf first narrows the same catalog to the free category.

    searchQuery · category === free
  3. 03

    Register or sign in for the full collection

    The course route redirects readers without local account state to signup. The server checks duplicate emails, hashes new passwords, and compares credentials during login.

    POST /user/signup · /login
  4. 04

    Add once, review, and remove

    The cart context ignores a second add for the same book ID, persists the list, and supports removal. The cart view totals prices before the unconnected checkout action.

    CartContext · localStorage

03 / Architecture

Four layers carry the prototype.

The reviewed source separates routed React views, shared browser state, Express handlers, and MongoDB models.

Interface React + Vite

Catalog cards, search, signup, login, cart review, and responsive views.

→
State Router + contexts

Route access, shared search, signed-in reader state, and cart persistence.

→
API Express controllers

Book retrieval, reader creation, credential comparison, CORS, and JSON parsing.

→
Data MongoDB + Mongoose

Book fields, unique reader emails, and password hashes stored through two models.

04 / Constraints

The current boundary is visible in the code.

These limits come from the reviewed snapshot. They are not claims about users, sales, production traffic, or business outcomes.

Configure before deployment

Catalog and account requests point to a localhost API address in the client. A deployed version would need a configurable public API base.

Local access, not server sessions

Route access is based on reader data in local storage. The source does not issue or validate a session token or cookie.

Filter after fetching

The book endpoint returns the full collection. Search and the free-books category filter both run in the browser.

Stop before purchase

The cart calculates a total and renders a checkout button, but the source has no order model, payment integration, or checkout handler.

Add automated checks

The backend test command is still a placeholder, and the reviewed snapshot contains no app-level test suite.

Keep credit bounded

Public history contains one repository-wide snapshot commit, so it does not support a contribution percentage or team-size claim.
