Technical walkthrough · EcoTrace

Put a deterministic boundary around model output.

EcoTrace's hard problem is not making one Gemini call. It is turning a probabilistic response into three non-negative numeric categories before that result becomes an account-owned database record.

01 / The hard problem

A typed interface cannot trust a model-shaped answer.

A model request can fail, return no text, produce malformed JSON, or put an unexpected value in a numeric field. EcoTrace narrows that uncertainty before the controller calculates a total or saves a record.

Risk 01

Missing or malformed response

An empty response throws. JSON parsing and the model request share one catch path into the local fallback.

Risk 02

Wrong numeric shape

Each category passes through Number, defaults to zero, and is clamped at zero or above.

Risk 03

Unscoped persistence

The controller reads the authenticated ID and stores it as userId on the footprint record.

02 / The boundary

Constrain early, normalize once, defend again.

The source uses several small checks rather than asking one layer to make an external response trustworthy by itself.

  1. 01

    Request boundary

    Reject unusable input before the model call.

    The route runs Zod validation after JWT authentication. The activity value must be a trimmed string with at least three characters.

    calculateFootprintSchema
  2. 02

    Response boundary

    Ask for one explicit response contract.

    The Gemini request sets an application/json response type and requires three number fields plus a suggestions array.

    responseSchema
  3. 03

    Domain boundary

    Normalize before the data leaves the service.

    Parsed categories become numbers, missing or non-numeric values become zero, negative values are clamped, and non-array suggestions become an empty list.

    CarbonFootprintResult
  4. 04

    Persistence boundary

    Repeat the invariant where the record is made.

    The total utility clamps and rounds the three categories. The Mongoose model also requires every emission value and enforces a minimum of zero.

    sumEmissions · FootprintSchema

03 / The tradeoff

Keep the flow available, give up semantic nuance.

When the Gemini key is missing or the request throws, the service returns a deterministic keyword-based estimate with the same result shape.

What the fallback buys A predictable development path.

Local work can exercise the controller, total, persistence, and interface without a model request. The service tests can also assert exact category values for known keywords and API exceptions.

↔
What the fallback costs Fixed values instead of context.

The fallback checks whether words such as car, energy, or food appear. It does not parse distance, quantity, duration, or intensity, and it returns the same three suggestions.

Decision

Use the fallback to preserve a testable end-to-end shape, not as evidence of estimate accuracy. That boundary is why the portfolio describes EcoTrace results as estimates rather than an environmental audit.
