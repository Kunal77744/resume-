Case study · MERN / Full Stack Developer

A daily note becomes a traceable footprint.

EcoTrace is a TypeScript MERN application that turns a natural-language activity log into estimated energy, transport, and food emissions, saves the result to an account, and brings it back through history, challenges, and a leaderboard.

01 / The brief

One input, then a complete account-level loop.

The code frames a clear product problem: a person needs to describe everyday behavior quickly, understand an estimated category breakdown, and return later to see what has changed.

Interface

React views with guarded routes

Registration and login lead into protected calculator and dashboard views. Session state is restored from a stored token, then checked against the profile API.

Server

Express APIs with account ownership

JWT middleware protects footprint routes. History queries and deletion both include the authenticated account identifier.

Feedback

History, points, and next actions

Saved logs become dashboard totals and an SVG category breakdown. Challenges, rank progress, and suggestions give the person something concrete to do next.

02 / Core flow

Follow one activity log through the stack.

Each step below maps to a public route, controller, service, model, or view in the pinned source revision.

  1. 01

    Establish an account session

    Register or sign in, receive a JWT, and restore the session through the current-user endpoint before entering protected views.

    POST /api/auth/login
  2. 02

    Describe the day in plain language

    The calculator validates a short activity description and sends it to the protected footprint endpoint.

    POST /api/footprint/calculate
  3. 03

    Structure, total, and persist

    The service requests a strict JSON shape from Gemini, clamps category values to zero or above, totals the result, and saves a MongoDB record tied to the account.

    Footprint + User
  4. 04

    Bring the record back as feedback

    The dashboard fetches history, calculates category totals, renders a responsive SVG chart, and keeps deletion scoped to records owned by the signed-in account.

    GET /history · DELETE /:id

03 / Architecture

Small layers with visible boundaries.

The repository keeps client views, API routes, domain logic, persistence, and external AI parsing in separate modules.

Client React + TypeScript

Router guards, auth context, calculator, dashboard, and native SVG.

→
API Express + TypeScript

Validation, rate limiting, JWT middleware, controllers, and errors.

→
Data MongoDB + Mongoose

User, footprint, timestamps, ownership queries, and indexed account IDs.

↗
Analysis Gemini 2.5 Flash

Structured category output, suggestions, and a deterministic local fallback.

04 / Constraints

The code is explicit about its limits.

These are engineering constraints visible in the source, not claims about usage, business results, or calculation accuracy.

Estimate, don't overstate

Activity text produces estimated emissions. Missing categories default to zero, and the interface does not present the result as a measured environmental audit.

Keep development testable

When no Gemini key is available, a deterministic keyword-based fallback preserves the flow without making a network request.

Contain account data

Protected history and deletion operations use the authenticated account ID. Passwords are hashed before storage.

Mock the external edge

Integration tests replace the AI service and check authentication, validation, successful calculation, history, and deletion paths.
